# Trusted pre-execution delegation

`cbr-execution-delegation-contract-v1` and
`cbr-preexecution-delegation-receipt-v1` provide a local CBR control-plane
binding for explicitly delegated execution.

## Admission boundary

The delegation contract is optional. When supplied, it must be admitted in the
task's first atomic queue write through `cbr enqueue
--delegation-contract-json`. Its task id, public task revision and class,
authority/policy/execution/review revisions, and side-effect boundary are
digest-bound. The stored contract is immutable after enqueue. A legacy task
cannot acquire one later, and completed history cannot be backfilled.

The contract does not authenticate an external issuer. It records
`external_issuer_authenticated=false` and `global_provenance=unknown`.

## Claim and invocation barrier

For a contract-bearing task, the runner requires an isolated task worktree.
After claim and exact worker/target/config resolution, it appends one canonical
receipt for the attempt and saves the task while holding the queue lock. Only
after that durable save does it capture and bind the `pre_worker` mutation
snapshot. The runner validates the completed receipt/snapshot phase sequence
again before any post-claim trigger or worker backend call.

The receipt binds:

- task id, task revision, attempt and immutable contract digest;
- exact worker family, a deterministic worker-identity digest, and target id;
- digests of the resolved target snapshot, execution config and command
  contract;
- claim id, lease sequence, revision set and predecessor receipt.

`recorded_at` is generated by the runner. It is not accepted from a caller and
does not participate in `receipt_id`, so the semantic identity is deterministic.

If receipt creation, the first durable save, snapshot capture, binding, or
pre-invocation validation fails, the worker is not invoked. A stale process that
ended after the receipt save but before the snapshot is marked
`attempt_recovered_before_pre_worker`; a later attempt must append a new receipt
chained to the prior receipt. Existing orchestration receipts are not
reinterpreted as delegation receipts.

## Reporting and non-claims

`cbr execution-report --purpose diagnostic|audit` shows receipt-only crash
states as insufficient evidence even when no `last_run` exists. Routing reports
remain limited to comparable completed execution evidence. The projection is
additive and report-only: it grants no canary, promotion, selection, dispatch,
live/default routing, queue-policy, cooldown, wake, reservation, retry, provider
probe, deployment, publication, credential, or external identity authority.
